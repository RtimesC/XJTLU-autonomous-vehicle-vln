# 项目决策记录

## 已确定

### D-001：实验平台

第一阶段使用人在回路的平台：人携带 Ubuntu 电脑和 RGB-D 相机，系统生成一条单步指令，人执行后反馈结果。

### D-002：核心与执行平台解耦

VLM 输出与执行平台无关的导航意图。当前由人工执行适配器解释，未来可由小车底盘或云台适配器解释。

### D-003：显式区分身体和相机运动

导航意图必须能表达“只转动相机”和“身体移动”之间的区别。第一阶段不允许把两者隐含合并成一句无法解析的动作。

### D-004：先支持回放和模拟

在确认具体相机型号、SDK 和 VLM 后再接入实时设备。核心代码先支持离线观测和确定性模拟，避免把未确认依赖写死。

### D-005：每轮只执行一个意图

一次 VLM 决策只产生一个导航意图。执行完成或失败后，才进入下一轮观察和记忆更新。

## 待确认

### Q-001：RGB-D 相机

需要确认相机型号、Ubuntu 版本、驱动/SDK 状态和 RGB-D 对齐方式。

### Q-002：VLM 后端

需要确认使用远程 API、本地模型，还是先使用人工/模拟策略进行流程验证。

### Q-003：交互界面

当前建议使用本地网页界面；需要根据电脑使用方式决定是否改为桌面界面。

### Q-004：未来小车执行接口

需要确认底盘、云台和停止链路的实际消息接口。当前不写入具体速度单位或车辆 topic。

### Q-005：动作粒度

当前使用 `OBSERVE`、`ADVANCE`、`INSPECT`、`STOP` 四种意图；真实实验前需要根据场地和人的操作方式调整。

### D-006：当前相机

第一阶段相机确定为 Intel RealSense D455f。相机驱动、采集 SDK 和 RGB-D 对齐方式暂不在核心层写死，放入相机适配器。

### D-007：VLM 接入路线

先采用远程 VLM API 作为主实验后端，用于快速验证 ReasonNav 启发的高层推理和历史记忆设计；同时保留本地模型适配器接口。本地模型先用于离线回放和延迟/成本对比，不作为第一阶段实时实验的前置条件。

### D-008：交互界面

优先采用运行在 Ubuntu 本机的本地网页界面。浏览器只访问 localhost，界面展示当前 RGB-D 观察、导航指令、历史摘要、执行确认和停止按钮。它比绑定某个桌面 GUI 更容易迭代，也便于以后连接车辆执行适配器。

### D-009：开发端与运行端分离

- macOS 是代码开发、静态检查、单元验证和离线回放端。
- Linux 是真实运行端，负责连接 Intel RealSense D455f、采集实时 RGB-D、调用 VLM 和运行实验。
- 代码仓库必须能够在没有相机、ROS 或 Linux 专用组件的 macOS 环境中导入核心模块。
- RealSense、ROS、车辆驱动和其他平台依赖只能通过可选适配器加载，不能写入核心数据契约。

### D-010：跨平台路径和配置

- 不在代码中写入 macOS 或 Linux 的绝对路径。
- 数据目录、API 地址、模型名称和设备参数通过配置文件或环境变量提供。
- 实验记录使用相对路径，保证 macOS 生成的离线回放数据可以复制到 Linux。
- 不把 API key、设备序列号或个人路径提交到仓库。
