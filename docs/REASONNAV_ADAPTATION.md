# ReasonNav 论文到本项目的适配边界

## 论文中的系统

ReasonNav 将系统分成低层和高层两条流：

- 低层负责定位、建图、物体检测和路径规划
- 高层 VLM 接收地标记忆 JSON 和俯视地图图像
- VLM 选择下一个地标
- 按地标类别调用预定义行为原语，例如探索 frontier、读取房间门牌、读取方向标志或询问人员

论文的核心不是让 VLM 直接输出精确坐标或连续运动量，而是让 VLM 在抽象的地标和行为空间中做高层选择。

## 官方实现的模型路线

官方仓库 README 记录了使用 OpenAI API 调用 GPT-4.1，并使用 Bing Search API。系统在 ROS 2 中运行，真实机器人和 Isaac Sim 共用高层 ReasonNav 节点。

## 本项目的第一阶段改造

本阶段暂不使用 SLAM、Nav2 或车辆底盘，因此不能声称复现完整 ReasonNav。我们保留以下核心思想：

1. 用结构化地标记忆代替无约束的长对话历史
2. 让 VLM 选择高层导航意图，而不是输出精确速度
3. 为观察、读取标志和询问人员设计行为原语
4. 每次只执行一个意图，然后重新观察和更新记忆

当前由 D455f 提供 RGB-D 观察，由人执行意图。后续可以逐步加入更可靠的地标检测、定位和车辆适配器。

## 第一阶段推荐输入

```text
目标房间
当前 RGB 图像
深度摘要和目标距离
已确认的地标记忆
最近动作及执行结果
当前执行平台状态（human_carried）
```

## 第一阶段推荐输出

```text
一个结构化的高层导航意图
目标地标
相机运动或身体运动的归属
执行指令
完成条件
停止标志
```

## 远程 API 与本地模型的安排

- 远程 API：第一阶段主实验，优先验证推理质量和记忆设计
- 本地模型：离线回放、成本/延迟对比和网络不可用时的备用实验
- 两者必须共享同一个输入输出契约，避免更换模型后改变实验任务定义
